# 確定給与データ加工・引渡しフロー v1.0

更新日：2026-09-24

## 目的と担当範囲

「03_給与計算と通勤手当の記録」は給与確定までを担当する。このタスクは確定後のデータ取得、照合、形式修正、5区分への分割保存、次工程への引き渡しを担当する。
作業者はこのタスクの担当者。判断が必要な場合の確認先は依頼者。次工程の受領者・引渡し先は未確認。銀行へのアップロード・振込実行は本フローの完了範囲に含めない。

本書は会話で合意した運用フロー。既存スクリプトの改修完了を意味しない。説明と実装に差がある場合は、現在の動作・影響・修正案を実装前に報告し、依頼者の指示を受ける。

## 1. 確定給与の受け取り

- 対象法人、給与対象月、支給日、確定済みであることを確認する。
- 対象者と振込額の確認根拠を引き継ぐ。給与対象月と支給月を混同しない。
- 実行時の対象月・支給日が不明なら確認してから出力する。

## 2. MF給与から出力

最新指示により、画面操作は通常のChromeを基本とする。認証済みセッションは再利用し、再認証時は承認済みの `実行環境で承認済みの認証用.env` のMF_ID / MF_PASSを非表示で使用する。秘密値は表示・記録しない。過去のアプリ内ブラウザ優先指定は本指定で置き換える。

1. 「支払業務」→「給与・賞与」を開く。
2. 対象・支給日を選び、該当する確定給与にチェックする。
3. 振込方法は「給与振込」。レコード設定はデフォルトのままとし、実際の表示値を記録する。
4. 支払口座は「ステラリホープカブシキガイシャ」にチェックする。同名候補が複数なら口座を確認する。
5. 振込日を確認して「FBデータ作成」（画面によって「FBデータ出力」）を一度押す。自動ダウンロードを待ち、取得リンクを追加で開かない。
6. ZIPを保存し、元ファイルを保持したまま専用の作業フォルダへ展開する。

原本ZIP、FBデータTXT、支払先一覧CSVを保持する。TXT・CSVをExcel等で開いて上書き保存しない。

## 4. 全件照合と本人確認

### TXTと支払先一覧CSV

**振込先情報の取得元はTXT、本人識別情報の補完元はCSV。**

- TXT：銀行コード（4桁）、支店コード（3桁）、預金種目、口座番号（7桁）、名義カナ、振込金額。既存9/25 ZIPの全93明細で確認済み。分割後の銀行・支店・預金種目・口座番号・金額はTXTから引き継ぐ。
- CSV：振込先金融機関名、従業員番号、従業員名、口座番号、口座名義人、口座名義人（フリガナ）、振込額、振込件数。銀行コード・支店コード・預金種目の列はないが、TXTにあるため振込情報の欠損ではない。

TXTとCSVは共通する口座番号・金額・名義カナで全候補を比較し、双方向で一意な1対1対応を確認する。CSVの合計行は明細から分離して集計検証する。銀行名は確認済みコード対応があれば補助照合する。CSVにない支店・預金種目等を直接照合した扱いにはしない。

番号は文字列として先頭ゼロを保持し、所定桁数に基づいて比較する。緩いカナ一致だけで決めない。該当なし・複数候補・未対応の余りがある場合は停止し、MFの従業員口座情報等で追加確認する。先頭候補を自動採用しない。

### 支払先一覧CSVと名簿

従業員番号・社員IDを軸に、氏名、カナ、記録された旧姓、利用可能な追加情報で本人を裏付ける。番号だけの一致、氏名だけの一致で矛盾を無視しない。

同一名簿内と名簿間のカナ重複を検出し、候補をすべて保持する。全半角・空白の違いと、濁点・小文字を無視した緩い比較を区別し、緩い一致だけで確定しない。

結婚等で名簿が新姓・口座名義が旧姓でも直ちに別人としない。旧姓記録などで裏付け、一意に確認できなければ停止する。名簿の姓変更だけを理由に口座名義を書き換えない。

## 5. 5区分に振り分け

| 出力区分 | 判定条件 |
|---|---|
| 川島A型 | 拠点が確認でき、沖洲以外のA型利用者 |
| 川島B型 | 拠点が確認でき、沖洲以外のB型利用者 |
| 沖洲B型 | 沖洲のB型利用者 |
| 沖洲勤務職員 | 勤務拠点に沖洲を含む職員 |
| 沖洲勤務職員以外 | 勤務拠点が確認でき、沖洲以外の職員 |

振込対象者の拠点空欄、利用者区分空欄、沖洲A型など5区分外、本人不明、情報矛盾は停止・報告する。例外設定で空欄や矛盾を黙って通過させない。

個別例外はリポジトリ外の承認済み台帳で管理する。社員番号・氏名・根拠・適用期間を照合し、一般の空欄許容へ拡大しない。

## 6. 形式修正と出力前検証

本人との対応関係を確定してから加工する。

- TXTのヘッダ種別コードを **11（給与振込）から21（総合振込）** に変更する。入力が11以外なら想定外として報告する。
- TXTはShift-JIS、各レコード120バイト、CRLF形式に整える。
- 名義のタブ・余分な空白・中黒等を既存ルールに沿って整形し、変更前後を記録する。実名義の訂正は根拠を確認する。
- 分割先ごとにトレーラの件数・金額を再計算する。
- 全件の分割先確定、重複・欠落なし、元データと分割後の件数・金額一致を出力前に検証する。

既存スキルはGMOあおぞらの一括振込向けの形式を想定している。銀行仕様との適合性は別途公式資料で確認し、今回未確認のまま適合済みとは扱わない。

## 7. 分割保存と再確認

検証が完了してから、次を今回の実行専用フォルダに出力する。

- 全銀形式TXT：5区分各1ファイル（種別21）。
- GMO指定形式CSV：5区分各1ファイル。銀行コード、支店番号、預金種目、口座番号、受取人名、振込金額の6列。見出しなし・Shift-JIS。
- 振分結果CSV：社員番号、氏名、分割先、金額、本人照合・振分根拠、変更内容を確認できる一覧。
- 実行レポート：使用資料、対象月・支給日・振込日、件数・金額、照合結果、変更点。

**CSVに振込種別欄はなく、11→21の変更はTXT側に入る。** TXTとCSVは同じ振込の代替形式であり、両方を重複して振込に使用するものではない。

保存後もファイルを読み直して形式・件数・金額を検証する。0件区分がある場合はレポートに明記し、銀行に渡す扱いは確認する。過去の出力と混在させない。

## 8. 停止時の報告と完了条件

停止時は銀行取込用の完成ファイルを引き渡さず、確認レポートを保存する。

報告項目：対象者／社員番号、問題、照合候補と根拠、足りない情報、提案する対応、依頼者に判断してほしい事項。

完了チェック：

- [ ] 対象法人・対象給与・日付・支払口座が正しい。
- [ ] 全振込行と対象者を一意に照合できた。
- [ ] 拠点・利用者区分の空欄と未解決事項がない。
- [ ] 5区分の振分が確定し、合計件数・金額が原本と一致する。
- [ ] TXTの種別21・120バイト・文字コード・改行とCSVの6列を保存後に確認した。
- [ ] 名義修正と例外適用を報告した。
- [ ] 原本、加工済みファイル、照合・振分結果を区別して保存した。
- [ ] 受領者・引渡し先と使用形式を確認し、引渡しを記録した。
