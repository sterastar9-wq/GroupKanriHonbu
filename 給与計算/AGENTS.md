# 給与計算の共通運用ルール

- 通常Chromeを使用し、認証済みセッションを再利用する。再認証時は実行環境の承認済み.envからRAKUCO_ID / RAKUCO_PASS、MF_ID / MF_PASSを非表示で取得する。値・Cookie・認証URLを記録しない。OTPは依頼者へ引き継ぐ。
- 給与工程は01→02→03→04。勤怠月・支給日・法人・範囲・変更権限を実行ごとに記録する。末締め翌月25日払い。過去月を当月条件で上書きしない。
- ブロックや操作接続障害が出たら停止・報告する。自動再試行、連打、取得リンクの追加クリックをしない。タイムアウト後は結果不明であり、成功や未送信と断定しない。
- MFへの取込は承認済み・検証済みCSVだけ。選択名を画面で確認し、省略される場合は同一ハッシュの短い名前のコピーで確認する。DOM files空配列だけで未選択と断定しない。
- インポート→上書き確認OK→処理待ち→成功表示→対象日の実打刻照合。OKを試みたことと受理確認を区別する。結果不明なら反映確認が先であり、同じファイルを自動再送しない。
- 給与確定・振込は別の権限。今回の模擬テストでは確定ボタンを押さない。ルール登録やファイルpushは給与変更・確定・振込の許可ではない。
- 同姓同名・改姓はID、氏名、旧姓記録等で裏付ける。011と11など先頭ゼロの異なる番号を自動統合しない。拠点空欄や複数候補は停止・報告する。
- 説明と実装が異なる場合、現状・影響・修正案を実装前に報告し、依頼者の指示を受ける。
- 給与実データ、原本ZIP、名簿、口座情報、個人別例外、.env、実行ログはGit管理外に置く。
