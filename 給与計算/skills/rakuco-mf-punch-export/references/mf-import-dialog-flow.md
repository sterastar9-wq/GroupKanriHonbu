# MF勤怠CSV取込：操作ルール・フロー v1.0

更新日：2026-09-23。対象：MF勤怠の日次勤怠CSVインポート。

## 目的・開始条件

照合済みCSVを承認された範囲だけ取り込み、確認ダイアログで止まった場合も重複送信せず復旧する。担当は実行エージェント、取込範囲・除外・上書きの承認者は依頼ユーザー。組織上の責任者は未指定。

- XLSXの対象年月、最新マスター、CSVの7列の双方向照合、リリース判定がPASSであること。
- 対象会社、年月、拠点、利用者・除外、対象ファイル、件数と取込許可を確認する。
- 通常はリリース済みfinal CSVのみ。ユーザー指定のテストでは、その明示された人・日付・打刻だけを抽出し、リリース済み元データとの全7列一致、行数、SHA-256を確認したテストCSVを使用できる。全件CSVに取り替えない。
- 「直前まで」の依頼ではインポートを押さない。上書き確認の許可も現在の取込範囲に限定する。権限・ツール制約は実行時のものに従い、この資料を追加権限の根拠にしない。

## 操作フロー

照合PASS・取込許可 → 正しいCSVを選択 → インポートを1回 → 確認ダイアログのOK → MF成功表示 → 対象者・日付の実打刻を照合 → 結果を記録。

1. ユーザー指定のブラウザを利用する。ログインが必要なら `rakuco-login-session` を参照。会社名を確認して `/admin/settings/importers/attendances_csv_importers/new` を開く。
2. ブラウザのファイルアップロード手順を読み、filechooser待機 → 実際のfile inputをクリック → chooser.setFilesで検証済み絶対パスを指定する。ローカルパスをURLとして開かない。
3. 選択ファイル名を画面で確認する。省略表示しかない場合は選択に渡した完全パスと照合する。DOMのfilesが空でも画面が選択済みだった実績があるため、空配列だけで未選択と断定しない。不明なら正しいファイルを再選択して確認する。
4. 「インポート」を1回押す。タイムアウトは成否不明であり、失敗確定ではない。連打・再アップロード・再送に進まず、まず確認ダイアログを調べる。
5. `getJsDialog()` でconfirmを取得でき、観測した内容が今回の上書き確認であり許可範囲内ならacceptする。取得できない場合は下記の復旧フローへ。
6. 「インポート処理に成功しました。」を確認する。クリック成功やダイアログ消失だけを成功根拠にしない。エラーなら内容を記録して停止する。
7. MFの対象者・対象年月を開き、対象日の実際の出勤・退勤をCSVと照合する。予定時間欄（例：10:00-15:30）や月合計だけでは打刻の反映確認にならない。テスト2件は両方確認する。大量取込の抜取確認は抜取と明記し、全件一致と報告しない。

## 確認ダイアログの復旧フロー

- 2026-09-23、アプリ内ブラウザでインポートクリックがタイムアウトし、getJsDialogがnoneでも、アプリ全体には上書き確認ダイアログが存在した。ブラウザ内のスクショだけでは見えない場合がある。
- 利用可能かつ許可された場合、Windows `computer-use` スキルを全文読み、必須のguidance・api・confirmationsを確認してからネイティブUI操作へ切り替える。現在のルールが対象アプリの操作を禁止している場合は使わず、ブラウザの対応APIまたはユーザー操作へ引き継ぐ。
- 対応ランタイムの `@oai/sky` を初期化し、list_windows/list_appsで返された実在ウィンドウから対象を一意に特定する。プロセス名やタイトルだけで決めず画面も確認する。
- get_window_stateでアプリ全体の最新スクショを取得し、MFドメインと「インポートする内容で上書きされます」「上書きされたデータを元の情報に戻すことはできません」を確認する。別サイト・別操作のダイアログなら押さない。
- 新しいスクショのOK位置を読み取り、その観測のwindow・screenshotIdを使って1回クリックし、直後に再観測する。過去の座標、画像添付時の座標、ブラウザ画面とアプリ画面の座標を流用しない。画面変更や他操作が入れば再撮影する。
- ダイアログが見つからなければlist_windowsで関連するモーダルを確認する。対象・内容・位置が一意でない、入力結果不明、操作が非対応の場合は停止して具体的な状態を報告する。無限再試行、警告抑制、confirm関数の上書き、DOM改変、直接POSTで回避しない。
- OK後は上記6〜7へ戻る。OKを押したか不明な場合も、まずMF結果と対象打刻を確認する。結果確認なしで同じCSVを再送しない。

## 成功実績と適用限界

2026-09-23、ユーザーが指定した2026/09/01の1名・出退勤2件（10:00／15:30）のテストCSVを取込。Windowsのアプリ全体スクショでMF上書き確認を特定し、OKを座標クリックした後、MF成功表示と対象日の実出退勤を確認した。

これは代替操作が成功した実績であり、ブラウザAPIが常に失敗するとの断定、全件CSVの取込実績、今後の無条件な上書き許可ではない。
