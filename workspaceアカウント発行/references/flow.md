# 実行フロー

## 1. 社員番号・名前の受領 → 照合

貼り付け対象だけを一覧化し、台帳の社員ID・氏名・D列・在籍・AB/ACを照合する。現在の行を確認し、管理コンソールで既存アカウントを検索する。

- 一意に一致、未発行、読み確定 → 2へ。
- 既存あり、台帳欠落 → 作成せず4へ。
- 既存あり、台帳一致 → 既存一致を報告して次へ。
- 本人・読み・アドレス衝突が未解決 → 当該者だけ必要な確認を求める。

## 2. フォーム準備 → 引き継ぎ

直前の存在確認後、同じ管理タブで作成フォームを開く。名・姓・ローカル部・`steragroup.co.jp`を入力し、手動パスワード欄を表示する。初回変更必須を選べるなら選択しチェック状態を確認する。毎回のDOM/画面から要素を特定し、過去のタブID・座標・要素番号を固定しない。

最終画面を確認してから次の形式で表示する。

    社員番号：{社員ID}　{氏名}
    メール：{完全なメール}
    初期パスワード：
    （実際の規定値だけを単独コードブロックで表示）
    この値をパスワード欄へ貼り付けて作成してください。作成後は「作成した」と報告してください。

初回変更必須が未選択ならチェック依頼を添える。パスワード未入力のまま本人操作用タブを保持する。画面が未準備なら準備できたと言わない。

## 3. 作成報告 → 登録確認

対象の引き継ぎ中の「作成した」「次」は、当該者の完了報告として登録確認へ進む。「全員登録できた」なら保留対象全員を確認する。対象が一意なら聞き直さない。

未保存フォームが残る場合は入力を消す移動・再読み込みをしない。成功表示・一覧・詳細で本人、アドレス、状態を確認する。結果不明なら既存検索し、再作成ボタンを押さない。登録未確認なら発行済みと記録せず、障害と再開地点を伝える。

## 4. 台帳更新 → 保存確認

社員ID・氏名で行を再特定し、AB/AC/AE/AFを読む。ACの異なる値は無断上書きしない。実アドレスをAC、ABを「有」、AEを実更新日、AFを「Codex」にする。AD・AGや無関係なセルを保持する。

Office編集画面での確認済み手順：

1. 名前ボックスで有限範囲を指定してEnter。
2. DOM/画面で指定範囲が選択されたことを確認してからコピー・貼り付けする。
3. 値のみ貼り付け後に画面状態を取得する。別範囲の指定前にも編集中でないことを確認する。
4. AB:ACとAE:AFを別々に扱い、ADを巻き込まない。
5. 対象範囲を再選択・コピーして期待値と照合し、ドライブへの保存済み表示を確認する。

2026-09-29には範囲選択とコピーを状態確認なしで続け、範囲文字列がセルへ入力された事例があった。選択後の状態確認を挟み、読み戻しで検証する。同種の事故は変更前に読んだ値または今回の確定更新値で修復し、周辺の保持を確認する。

## 5. 完了通知・次の対象

保存・読み戻し後に「{社員ID} {氏名}：登録確認・台帳更新完了（{メール}）」と台帳リンクを通知する。複数名の途中なら次の未完了者の準備へ進む。保存失敗なら「登録済み・台帳未反映」と明示し、4から再開する。

本人向け案内を求められたら、1人ずつコピーできるコードブロックで以下を作る。初期値の根拠はユーザーの作成報告とその際の指定値で確認する。既存アカウントのパスワードを規定から推定しない。既存者で初期値不明なら当該者の案内だけ保留する。

    {姓}さん、お疲れさまです。
    会社用のGoogle Workspaceアカウントを作成しました。

    メールアドレス：{確認したメール}
    初期パスワード：{ユーザーが設定した初期値}

    初回ログイン時に、必ずパスワードを変更してください。
    よろしくお願いします。

完了通知はこの対話への報告。メンバーへの実配信や定期監視を勝手に開始しない。
